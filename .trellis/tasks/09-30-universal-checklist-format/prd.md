# 通用清单数据格式与页面文案

## Goal

让管理员用一份通用清单数据完成导入和发布，用户随后可以完成条目、记录心得和照片、回看进度和分享。数据格式支持待办、学习和出游等主题，OCR 只作为来源示例。页面简洁地呈现实际内容和操作。

## Background and confirmed facts

- 当前 `ChecklistWrite` 和 `ItemWrite` 已有主题、条目、可选地点等通用字段；条目支持 `place_kind="none"`，因此数据模型并非只能表示实体地点。见 `backend/app/schemas/catalog.py:12,53`。
- 现有 `/admin/lists/{list_id}/imports` 只能向已有清单导入条目，要求 `transcription_reviewed`，并使用 OCR 专属错误文案；导入后是草稿。见 `backend/app/schemas/imports.py:9`、`backend/app/api/routes/admin.py:317`。
- 公开浏览只返回已发布清单与条目；记录、进度和分享按清单/条目关系工作。见 `backend/app/api/routes/catalog.py:25,67` 与 `.trellis/spec/product/requirements.md`。
- 首页、页脚、条目详情及部分记录页面使用“故事”“探索”“体验”“在哪里”等固定说法，未必适合待办和学习清单。见 `frontend/src/features/checklists/pages.tsx:125,503,511,535`、`frontend/src/components/app-shell.tsx:114`。
- 现有产品规格把用户自建清单列为待定/后续候选，并规定默认由管理员维护公开清单。见 `.trellis/spec/product/requirements.md`。
- 当前进度由用户在某条目上的有效记录推导；创建记录必须填写心得或附照片。因此纯待办条目目前不能直接一键标记完成。见 `backend/app/services/catalog.py:19,46`、`backend/app/api/routes/checkins.py:80`。

## Requirements

1. **R1 通用格式**：一份带版本的 JSON 表示一张清单及其条目，支持文件上传和粘贴。公开字段说明、JSON Schema、最小模板及待办/学习/OCR 来源示例。清单和条目均有名称及稳定 key，地点、心得要求和 OCR 复核标记不作为通用必填字段。
2. **R2 导入和发布**：导入前能预览标题、条目数量和具体字段错误。合法输入在一次操作中创建整张草稿清单与条目，失败不留下部分数据。管理员明确发布清单及草稿条目，看到已发布/草稿/已下架数量；已下架条目不随批量操作自动重新发布。
3. **R3 使用通用条目**：所有主题复用既有照片、文字记录、进度、历史与分享。条目不要求有实体地点；资料更新和导入不得改写用户记录。
4. **R4 简洁页面**：移除用户指出的首页宣传大段、页脚口号、英文装饰副标题以及“故事/探索”式提示。按数据有无展示“详情”“地点”“建议”等区域；使用“清单”“进度”“记录”“记录时间”等普通标签。保留必要的隐私、状态、错误和真实来源提示。
5. **R5 权限**：首版仅管理员导入、检查和发布；普通用户使用已发布清单。服务端验证权限和 CSRF，不依赖按钮隐藏。
6. **R6 直接完成**：所有主题支持无心得/照片的直接完成，创建默认私人的记录，之后可补充内容。同一条目有有效记录即为已完成，重复记录不重复增加进度；完成操作的重试和重复点击不产生意外重复记录。用户主动添加多次记录的能力继续可用。删除最后一条有效记录后恢复未完成。
7. **R7 重复导入**：同一稳定清单 key 和相同内容重复导入返回既有清单，不重复创建、不覆盖管理员编辑，也不改变发布状态。相同 key、不同内容提示冲突并引导管理员到系统中编辑；不同 key 可代表不同清单。同清单内重复条目需给出具体位置。

## Acceptance Criteria

- [x] **AC1 → R1/R3**：模板、JSON Schema 与待办/学习/OCR 示例符合相同的 v1 契约，无地点清单不填写虚假地点或复核信息。
- [x] **AC2 → R2/R5**：管理员可以上传或粘贴 JSON，预览后导入完整草稿清单；非管理员被拒绝；字段错误定位到条目/字段，失败无部分写入。
- [x] **AC3 → R2**：发布动作明确包含清单和草稿条目，操作后公开目录可见这些内容；故意下架的条目仍不可见；草稿预览不对游客开放。
- [x] **AC4 → R7**：相同 JSON 的重复提交、空白/对象字段顺序变化和并发重试不会新建清单；相同 key 的内容变化产生冲突，既有编辑、下架状态和记录均保留。
- [x] **AC5 → R3/R6**：一份学习或待办清单的条目可直接完成、看到进度、后续补心得和照片、重复添加记录、回看历史和显式分享。直接完成默认私人，双击或重试不增加多条记录。
- [x] **AC6 → R3/R6**：记录无心得/照片时正常显示“已完成”；可编辑为空、移除最后一张照片，删除最后一条记录后进度恢复；公开分享仍遵守改私密/删除/隐藏即时失效和媒体权限规则。
- [x] **AC7 → R4**：首页直接呈现清单；手机和桌面的详情、记录、历史、分享及管理页面没有指定空泛文案，无地点条目不显示地点占位区域。
- [x] **AC8 → R2/R3/R7**：已有 OCR 清单及 172 条种子数据保持原 ID、来源、真实核实状态和历史；旧种子命令与复核导入接口兼容，不因新格式引入自动重导或重新发布。

## Scope boundaries

本次不包含普通用户建清单、私人/协作清单、导入文件同步更新、CSV/Excel、导出功能、任意字段编辑器、定时/周期待办、学习测评、自动抓取和实时资料核查。导入文件不携带用户记录或完成状态，也不导入图片二进制或远程图片；管理员仍可通过已有功能维护封面。
