# Backend Database Guidelines

## ORM and session lifecycle

The runtime uses PostgreSQL with synchronous SQLAlchemy 2.x and psycopg.
`backend/app/db/base.py` defines the shared `DeclarativeBase`;
`backend/app/models/tables.py` contains the current entities using
`Mapped[...]`, `mapped_column` and `relationship`. The cached engine in
`backend/app/db/session.py` reads `TABI_DATABASE_URL` through settings and enables
`pool_pre_ping`.

Request handlers receive `Annotated[Session, Depends(get_db)]`. The dependency
closes the session and rolls back/re-raises request failures. It does not commit
automatically: writes explicitly commit at their route or service boundary.
Examples are `backend/app/api/routes/auth.py` (registration),
`backend/app/api/routes/checkins.py` (record creation) and
`backend/app/services/checklist_imports.py` (atomic import).

## Query and transaction patterns

- Use SQLAlchemy `select`, `db.scalar`, `db.scalars` and `db.get`, as in
  `backend/app/api/routes/catalog.py`. Paginated lists use a separate count
  query, bounded limit/offset and a stable ordering with ID tie-breakers.
- Group viewer record counts in one query with `IN` and `GROUP BY`, as in
  `item_counts` in `backend/app/services/catalog.py`; completion counts active
  item IDs, while record counts include repeat experiences.
- Preserve visibility/ownership filters. Public catalog requires both list and
  item publication; public records exclude hidden/deleted rows; author history
  keeps archived item labels. See `api/routes/catalog.py`,
  `api/routes/checkins.py` and `services/checkins.py` under `backend/app/`.
- Use `flush()` to obtain IDs before creating dependent rows, then commit the
  complete operation. Universal imports create the list, items, links,
  relations, import identity and audit in one transaction.

Actual race recovery in `backend/app/services/checklist_imports.py`:

```python
    except IntegrityError:
        db.rollback()
        prior = find_import(db, payload.key)
        if prior is None:
            raise
        return _reuse(prior, digest)
```

The unique package key arbitrates concurrent imports. After rollback, equal
content reuses the immutable original IDs; different content returns `409`.
An unrelated integrity failure is re-raised when no winning import exists.
`create_checkin` in `backend/app/api/routes/checkins.py` similarly rolls back
before inspecting the existing user/idempotency-key row.

Direct completion locks the item before looking for an active user record;
batch publication locks the list and its items. The following statement is from
`complete_item` in `backend/app/api/routes/checkins.py`:

```python
item = db.scalar(select(Item).where(Item.id == item_id).with_for_update())
```

These are PostgreSQL transaction contracts, not guarantees provided by the
SQLite test fixture. Follow the existing lock order in the affected operation.

## Storage and naming

`backend/app/models/tables.py` is the source for current naming:

- Tables/columns use snake_case; most table names are plural (`users`, `items`,
  `checkins`, `audit_logs`). `Checklist` maps to `lists`; `Media` maps to `media`.
- IDs use `Uuid(as_uuid=False)` and string UUIDs from `new_id`; foreign keys name
  the target table/column explicitly. Dates use `DateTime(timezone=True)` with
  UTC application timestamps.
- Mutable JSON defaults use factories (`default=list`), not a shared list.
  Tags/missing fields are JSON lists; import item-key mappings are JSON objects.
- Existing named constraints are not generated by a global naming convention.
  Preserve names such as `uq_item_within_list`, `uq_checkin_idempotency`,
  `uq_checklist_import_package`, `no_self_relation` and `ix_items_list_sort`.
- Deleting a check-in sets `deleted_at`; unpublishing content preserves IDs and
  historical records. Do not replace this with cascading hard deletion.

For example, `Checkin.__table_args__` contains the per-user retry constraint:

```python
UniqueConstraint("user_id", "idempotency_key", name="uq_checkin_idempotency")
```

Check bounded storage values after normalization, not just their source input:
`schemas/checklist_format.py` and `services/checklist_imports.py` under
`backend/app/` enforce URL length, normalized name/address identity and signed
32-bit import sort values before writes.

## Migrations and validation

Alembic reads settings and imports model metadata in
`backend/migrations/env.py`. Revisions live in `backend/migrations/versions/`;
the current chain ends at `a748bd701acf_add_checklist_imports.py`. Two concrete
examples are `cf8b4151f81e_add_item_tags.py` (non-null JSON tags with an empty-array
backfill) and `a748bd701acf_add_checklist_imports.py` (additive identity table,
foreign keys and named uniqueness).

After a schema change, run `./hako python alembic upgrade head` and
`./hako python alembic check` with `TABI_DATABASE_URL` and `HAKO_NETWORK` explicitly
targeting an authorized isolated PostgreSQL instance. The Compose API entrypoint
also migrates before starting Uvicorn; it does not replace migration validation.
Connection setup and data boundaries live in
[development](../trellis-plus/development.md) and
[validation](../trellis-plus/validation.md).

`backend/tests/conftest.py` creates a fresh SQLite database per API test and
overrides `get_db`. `backend/tests/test_checklist_format.py` checks rollback and
retry behavior; `backend/tests/test_postgres_checklist.py` tests unique-key races,
late failure residue and completion row locks with real PostgreSQL. The latter
requires explicit `TABI_TEST_DATABASE_URL`, creates a UUID-named schema and drops
only that schema; absent configuration means skipped tests, not passed races.

## Common mistakes

- Reading a winning row before rolling back a failed transaction leaves the
  session unusable. Keep rollback before recovery queries.
- A pre-insert lookup does not replace a unique constraint under concurrency.
  Do not remove uniqueness or row locking because SQLite tests pass.
- Do not commit partial import rows or audit separately, hash current edited
  content on retries, or overwrite the original import mapping.
- `Base.metadata.create_all` is a test-fixture shortcut, not a migration path for
  existing data. Do not reset shared databases or volumes to bypass migrations.
- SQLite timestamps may be naive; the existing auth dependency normalizes them
  for expiry comparisons. Do not infer that production dates should lose UTC.
