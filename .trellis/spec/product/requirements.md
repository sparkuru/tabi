# 清单打卡系统：需求与验收

## 定位和范围

以清单组织目标，用户查看条目“是什么、在哪里、做什么”，随后为同一条目记录任意多次体验。首版以北京美食、周末游玩验证通用流程，但领域模型允许无实体地点的主题。手机浏览器是主要使用场景，桌面端支持浏览和内容管理。

首版包含邮箱密码账号、公开清单与条目浏览、个人进度、重复打卡、心得和照片、可选定位、个人历史、公开心得、单条分享及管理员内容管理。不包含自动抓取/实时校验商户资料、关注/私信、评论点赞、排行积分、路线规划、强制到场证明、任意字段编辑器、离线同步和原生 App。

待定：首版是否开放用户建清单；邮箱验证、找回密码、账号注销是否提前实施；地图与地点资料来源及费用/条款；违规内容处置和账号/图片保留期限。在明确变更前，公开清单由管理员维护，游客可浏览公开心得。

## 角色与访问

| 角色 | 能力 |
| --- | --- |
| 游客 | 浏览已发布清单、条目、公开心得及有效公开分享链接。 |
| 登录用户 | 追加打卡，查看、编辑、删除自己的单次记录，管理照片与可见性，回看历史。 |
| 内容管理员 | 创建、编辑、排序、发布或下架清单和条目，隐藏不适宜的公开记录。 |
| 系统管理员 | 管理账号与角色，查看操作审计，执行备份和恢复。 |

服务端逐次校验角色、记录所有权及公开范围。页面隐藏按钮不构成授权。公开资料只展示昵称和头像，不暴露邮箱。

## 领域不变量

| 概念 | 规则 |
| --- | --- |
| 清单 `list` | 主题、简介、封面、分类/排序与发布状态由管理员维护。 |
| 条目 `item` | 只属于一个清单；有名称、详情、推荐动作、分类和可选地点。同名同址但分属不同清单的条目不合并、不跨清单计数。 |
| 打卡 `checkin` | 一次体验对应一条独立记录；同一用户对同一条目可重复打卡，心得、照片和可选定位独立保存。 |
| 进度 | 一个清单内，至少有一条有效打卡的不同条目数；重复打卡仅增加记录次数。删除最后一条有效记录后，该条目恢复未完成。 |
| 历史 | 已有打卡的条目只能下架，不物理删除。清单或条目下架后，作者仍能从个人历史进入原记录；公开资料是否继续展示由下架原因决定。 |
| 地点 | 地址、区域、线上链接或无固定地点均可；客户端定位只是辅助资料，不能证明到场。坐标必须注明坐标系。 |
| 公开 | 单条记录默认仅作者可见；只有明确设为公开且未删除、未被管理员隐藏的记录才可公开浏览和分享。 |

## 首版功能清单

| 编号 | 必需行为 |
| --- | --- |
| ACC-01–03 | 邮箱密码注册/登录/退出与状态保持；昵称头像；服务端限制记录修改与管理员权限。 |
| LIST-01–03 | 浏览已发布清单；清单内关键词搜索、分类筛选、排序、条目状态与个人进度；管理员维护及下架。 |
| ITEM-01–05 | 条目详情、图片、标签、推荐动作、结构化可空地点、带标题外链、同清单关联项；编辑资料不改写历史心得。 |
| CHECK-01–06 | 任意多次打卡、默认/自填体验时间、可空心得与多张照片、主动授权的可选定位、单次编辑/删除、倒序和分类回看、次数展示、避免双击或网络重试产生意外重复；错误重试保留未提交表单。 |
| SOCIAL-01–05 | 每条记录独立选择私人/公开且默认私人；条目公开心得分页；稳定分享链接在改私密、删除或隐藏后失效；分享页不暴露精确定位、原图元数据或邮箱；管理员隐藏行为可审计。 |
| DATA-01–03 | 人工复核 OCR 来源后导入两种主题；同清单内查重、坐标核对、缺项标记、记录来源和核对时间；易变的价格、交通、营业信息标为带时间的参考资料，不能把未核实内容当作当前事实。 |

本次用户确认 `archive/ocr.md` 是首批完整记录。可将其中稳定的名称、区域和注明 OCR 来源的推荐作为**未核实现状的参考内容**公开；这不等于核实商户经营、具体地址、票价或车程。后续新 OCR 批次仍走逐条复核导入，现状核实时间仅在真实核查后填写。

后续候选：ACC-04 邮箱验证/找回/注销；LIST-04 收藏及用户/协作清单；ITEM-06 受控扩展字段；SOCIAL-06 社区互动。是否进入首版须单独决策。

## 页面与核心路径

清单首页 → 清单详情（筛选与进度）→ 条目详情（是什么/哪里/做什么、相关项、公开心得）→ 登录/注册 → 新建或编辑打卡 → 单次记录/分享 → 我的打卡与多次历史；管理员有清单、条目、隐藏及导入核对入口。普通页面应有可分享的固定 URL，首版不以搜索引擎收录为验收目标。拒绝定位或不上传照片均不能阻断提交。

## 首版验收场景

1. 游客能打开公开清单、条目、公开心得；打卡被引导登录。
2. 同一用户对北京美食的同一店打卡两次，两条记录均可回看，进度只增加一项，次数为两次。
3. 两个清单各有一家同名店时，一边的打卡不影响另一边的心得和进度。
4. 无定位、无照片的纯文字打卡和无心得的照片打卡均可成功。
5. 私人记录只有作者可读；公开分享可访问；改回私人、删除或管理员隐藏后链接不再展示内容。
6. 用户无法编辑他人记录；清单下架后作者仍可回看已有打卡。
7. 美食与游玩主题共用新建打卡和历史回看流程。
8. 连点提交或网络重试不会意外产生重复记录；失败时表单内容仍可重试。
