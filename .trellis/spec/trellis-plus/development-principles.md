# Development principles

本项目处于开发阶段；已有持久化数据库、私人照片、账号和公开分享契约，不能据此推断数据可丢弃或隐私可放宽。当前没有外部发布证据；后续按具体接口、数据和消费者记录兼容例外。

## Scope and implementation

- 只解决当前批准需求及有证据的近期需要。先检查并复用现有组件、API 客户端、模型、配置、错误处理、缓存和测试；修改实际执行路径，不平行实现服务，不引入猜测性的工厂、插件、缓存或回退链。
- 未发布且无兼容承诺的原型可同时调整实现与调用方并删除废弃路径；既有 OCR 稳定 ID、种子命令、权限、分享撤销、历史和媒体数据的保留边界，以产品规格及当前获批准设计为准。
- 开发环境不授权删除未知数据。仅已确定可丢弃且获授权的测试库可重建；真实数据迁移须保留历史，并先验证恢复路径。
- 不夹带无关重构、重命名、格式化、依赖升级或目录重排。新增依赖需解决标准设施、现有依赖或小型实现无法合理解决的具体问题。
- 清楚处理真实契约与合理失败，缺关键配置必须报错，不吞异常、不以成功默认值掩盖错误、不静默回退。

## Evidence and validation

修复前确认当前行为、实际执行路径与根因，能复现则复现；不能复现时标明假设和限制。不能同时改实现/契约/测试后用新测试证明旧故障。测试验证用户行为及契约，不能删除断言、屏蔽错误或 mock 掉被验证的行为。

使用 [验证资料](validation.md) 中最小有效检查和实际执行结果。构建、类型、单测、HTTP 200 各只证明自身范围；明确区分实现完成与验收通过。SQLite 单测不证明 PostgreSQL 行锁/约束；截图不证明手机交互路径。受控 fixture 可替代不可用依赖，但要写明边界。

检查保持适度：复用现有命令，仅为重要可重复行为增加持久测试，不为小改动增加新框架、checker、CI、审计系统或多轮代理评审。

## Development access and workspace

局域网开发沿用可配置的 host 发布，具体地址、Cookie 与 HTTPS 边界见 [开发资料](development.md)。测试若受登录或初始化妨碍，可使用独立测试账号和明确的开发配置；不能使用生产凭据、削弱生产默认值或跳过当前要验证的认证行为。

预存改动属于用户；不覆盖、回滚、清理未知文件或混入提交。README 属于用户展示材料，不主动改写。规则与命令只保存在本层，任务结果留在正常 task 证据中；不另建重复指南或 changelog。清理本轮临时调试文件，不删除未知材料。

开始或中断后先读 mainline、当前验收标准和共享政策；批准后的需求变化与验证结果按 [连续性](continuity.md) 更新，不能以实现偏差降低验收。结束时说明所请求行为、实际检查与未验证部分，并核实没有用户工作丢失、无关清理或意外依赖。
